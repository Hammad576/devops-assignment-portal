# DevOps Assignment Submission Portal

A Flask based assignment submission portal developed for the DevOps for Cloud Computing Lab Mid Term.

The project demonstrates Git and GitHub related development workflows, automated testing with GitHub Actions, 
and automatic delivery of CI test reports to a local machine using Cloudflare Tunnel.

## Features

- Submit assignments with name, registration number, assignment title, and submission URL.
- Validate submission information.
- Reject missing registration numbers and invalid URLs.
- Save valid submissions in a JSON file.
- Display saved submissions.
- Automatically run tests on every push to the `main` branch.
- Generate structured JSON test reports.
- Deliver both successful and failed CI reports to a local machine.

## Installation

Clone the repository:

```bash
git clone https://github.com/Hammad576/devops-assignment-portal.git
cd devops-assignment-portal
```

Create and activate a virtual environment:

```bash
python -m venv venv
source venv/bin/activate
```

Install dependencies:

```bash
pip install -r requirements.txt
```

## Run the Application

Start the Flask application:

```bash
python app/app.py
```

Open the application in your browser using the local address shown by Flask (normally `http://127.0.0.1:5000`).

## Run Automated Tests

Execute:

```bash
pytest -v
```

The test suite verifies:

1. A valid submission is saved successfully.
2. A missing registration number is rejected.
3. An invalid submission URL is rejected and not saved.

## Automatic CI Report Delivery

The project uses GitHub Actions to execute tests automatically whenever code is pushed to the `main` branch.

A local Flask report receiver accepts JSON reports generated by the CI workflow.

### 1. Start the Local Report Receiver

Open a separate terminal:

```bash
python receiver/receiver.py
```

The receiver listens on:

```text
http://127.0.0.1:5001
```

### 2. Start Cloudflare Tunnel

Open another terminal:

```bash
cloudflared tunnel --url http://127.0.0.1:5001
```

Cloudflare provides a temporary public HTTPS URL.

### 3. Configure GitHub Secret

In the GitHub repository, navigate to:

Settings → Secrets and variables → Actions → New repository secret.

Create this secret:

- Name: `REPORT_RECEIVER_URL`
- Value: Your Cloudflare Tunnel URL followed by `/report`.

For example:

```text
https://your-tunnel.trycloudflare.com/report
```

If the temporary tunnel URL changes, update the GitHub secret.

Keep both the local receiver and Cloudflare Tunnel running while executing the CI demonstration.

## Test Report

The CI workflow generates a structured JSON report containing:

- Repository name
- Branch name
- Commit SHA
- GitHub Actions run ID
- Timestamp
- Individual test results
- Failure messages
- Total, passed, and failed test counts
- Overall pipeline status

The report is automatically delivered to the local machine and saved as:

```text
test-report.json
```

Both passing and failing test reports are delivered.

## CI Demonstration

The project demonstrates three stages:

1. **Passing run:** All three tests pass.
2. **Failing run:** An intentional URL-validation defect causes one test to fail.
3. **Fixed run:** The defect is corrected and all three tests pass again.

This demonstrates that failed CI executions also generate and deliver their reports before the workflow exits with a failure status.

## Automated Email Test Reports

The GitHub Actions workflow also sends the generated JSON test report through Gmail SMTP.

### How it works

1. GitHub Actions executes the pytest test suite.
2. A JSON test report is generated.
3. The report is formatted by `receiver/generate_report.py`.
4. The formatted report is sent to the local receiver.
5. `receiver/send_email.py` attaches `formatted-report.json` to an email.
6. Gmail SMTP sends the email to the configured recipient.

### Required GitHub Secrets

Configure these repository secrets under:

Settings → Secrets and variables → Actions

| Secret | Description |
|---|---|
| `REPORT_RECEIVER_URL` | Cloudflare Tunnel URL ending in `/report` |
| `MAIL_USERNAME` | Sender Gmail address |
| `MAIL_PASSWORD` | Gmail App Password |
| `MAIL_TO` | Recipient email address |

Never store Gmail passwords or App Passwords directly in the source code.

### Email Notification

The email includes:
- Test execution status in the subject.
- Generated JSON test report as an attachment.
- Automated notification through GitHub Actions.
